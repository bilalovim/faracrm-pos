Файловое хранилище определяет, **где** физически лежат загруженные файлы. FARA поддерживает несколько провайдеров, и можно выбрать подходящий под вашу инфраструктуру.

## Провайдеры

| Провайдер | Когда выбирать |
|-----------|----------------|
| **Локальное (диск сервера)** | Просто и без настройки: dev, один сервер, чувствительные данные не должны покидать периметр. |
| **Google Drive** | Нужно облако и общие диски (Shared Drives), команда уже в экосистеме Google. |
| **Яндекс.Диск** | Хранение на территории РФ, уже есть подписка Яндекс 360, меньше задержки из РФ. |

> [!warning] Локальное хранилище на нескольких серверах не подходит: один рабочий процесс не увидит файлы другого. Для отказоустойчивости берите облако.

## Настройка Яндекс.Диска

1. Создайте OAuth-приложение на [oauth.yandex.ru](https://oauth.yandex.ru/) — получите `client_id` и `client_secret`.
2. Впишите их в карточку хранилища и пройдите авторизацию — система получит и сохранит токены доступа (access/refresh).
3. Токен доступа обновляется автоматически, повторно авторизовываться не нужно.

> [!info] Особенность Яндекс.Диска: файл адресуется **путём**, а не стабильным идентификатором. При переименовании папки «ссылка» на файл меняется — поэтому раскладку по папкам задавайте через Маршруты и не переименовывайте руками.

## Настройка Google Drive

1. Создайте OAuth-приложение в Google Cloud Console, получите client_id/secret.
2. Авторизуйтесь — FARA сохранит токены и будет обновлять их сама.
3. При необходимости укажите общий диск (Shared Drive) как корень.

## Локальное хранилище

Ничего настраивать не нужно — файлы лежат в папке на сервере. Важно лишь делать резервные копии этой папки. Облако с односторонней синхронизацией можно использовать как надёжный «оригинал», а локальное — как кэш.
