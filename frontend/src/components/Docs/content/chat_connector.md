**Коннектор** — это подключённый канал связи с клиентами: Telegram, Avito, ВКонтакте, MAX (МАКС), WhatsApp, электронная почта, телефония. Каждый коннектор описывает «как принимать и отправлять сообщения по этому каналу». Настраивается в разделе «Настройки → Коннекторы».

## Поддерживаемые каналы

- **Telegram** — бот (Bot API).
- **Avito** — переписка по объявлениям.
- **ВКонтакте** — сообщения сообщества (Callback API).
- **MAX (МАКС)** — три варианта: бот, агрегатор WAMM, официальный бизнес-API.
- **WhatsApp** — отправка по номеру.
- **Email** — SMTP (отправка) + IMAP (приём).
- **Телефония** — звонки (модуль телефонии).

## Как обрабатываются входящие

Когда клиент пишет вам, происходит цепочка (единая для всех каналов):

1. **Приём.** Внешний сервис шлёт **вебхук** на адрес FARA (у каждого коннектора свой). Для почты — периодический опрос IMAP.
2. **Определение коннектора.** Система понимает, к какому именно коннектору относится сообщение (по идентификатору канала / номеру).
3. **Поиск клиента.** По контакту отправителя (номер телефона, id в мессенджере) ищется **партнёр**. Сопоставление идёт по контактам с учётом формата телефона (см. ниже).
4. **Создание, если нужно.** Если клиента нет — создаётся партнёр, при необходимости **лид**, и открывается чат, привязанный к ним.
5. **Доставка операторам.** Сообщение появляется в разделе «Общение» у ответственных сотрудников — вживую (без перезагрузки) и с уведомлением.

> [!info] Один входящий диалог = один чат «записи», связанный с партнёром/лидом. Вся история в одном месте, вложения клиента сохраняются в хранилище так же, как файлы из внутренних чатов.

## Сопоставление контакта и коннектора

Чтобы верно «узнать» клиента и выбрать правильный канал ответа, используется тип контакта. Часть каналов работает по **номеру телефона** (телефон нормализуется — учитывается формат), часть — по внутреннему **id** пользователя канала (например, бот MAX). Поэтому у партнёра стоит указывать контакты в правильных типах (телефон, email, id мессенджера) — тогда входящее уверенно привяжется к нужной карточке.

## Написать клиенту первым

Для каналов, которые это позволяют (WhatsApp, бизнес-MAX и т.п.), доступна **отправка по номеру**: вы инициируете диалог, указав номер, и система сама заведёт/подберёт партнёра, лид и чат. Связь с внешним диалогом сохраняется, поэтому ответ клиента попадёт в тот же чат, а не «разъедется» в новый.

## Правила маршрутизации в лиды

Можно настроить правила, по которым новый входящий диалог автоматически порождает лид с нужной командой/стадией. Это удобно, чтобы обращения из разных каналов сразу попадали в правильную воронку.

## Проверка почтового коннектора

У email-коннектора есть кнопка **«Проверить соединение»** — она отдельно проверяет доступ по SMTP (отправка) и IMAP (приём), чтобы не гадать, почему письма не ходят.

> [!warning] Для каждого канала нужен свой доступ: токен бота, ключ сообщества, логин/пароль приложения для почты и т.д. Заводите их в настройках коннектора и держите в секрете — это доступ к переписке.
